## Context

`toControllerRoomView` и `toDisplayRoomView` уже сводят Colyseus-состояние к плоскому объекту и
валидируют его zod-схемой, а компоненты читают только результат. Значит источник этого объекта
подменяем, не трогая ни один компонент. Существующий
`isVisibleDemoMode(search, development, environmentValue)` задаёт образец dev-only флага, который
тестируется без DOM.

## Goals / Non-Goals

**Goals:** открыть любое состояние верстки обеих апп одним URL без сервера, переключать роль и фазу
без перезагрузки, гарантировать протокольную достижимость показанных состояний.

**Non-Goals:** живая симуляция `game-core` в браузере, визуальный редактор интерфейса, Storybook или
Ladle, любые изменения protocol и server authority, замена e2e-проверок на preview.

## Decisions

### Подмена на уровне view, а не на уровне транспорта

Preview заполняет тот же `view`-стейт, который заполняет `applyRoomState`, и оставляет
`roomReference` пустым. Мок Colyseus-клиента отклонён: он потребовал бы поддерживать форму
`MapSchema`/`ArraySchema` и повторять roomView-адаптер, то есть тестировать адаптер против самого
себя.

### Команды гасятся отсутствием комнаты, а не отдельной веткой

`sendControl`, `sendUpgradeVote` и `sendReady` уже начинаются с проверки `roomReference.current`, и
при пустой ссылке выходят молча. Поэтому preview не требует no-op обёрток: достаточно не открывать
соединение. Это же убирает риск, что боевой код и preview-код разойдутся.

### Гейт — только `import.meta.env.DEV` и query-параметр

`visibleDemo` дополнительно требует `VITE_VISIBLE_DEMO=1`, потому что он управляет автопилотом,
который вмешивается в реальную игру. Preview ничего не отправляет и не может повлиять на живую
сессию, поэтому третий флаг был бы лишним трением. Production отсекается `import.meta.env.DEV`.

### Фикстуры парсятся схемами протокола в тестах

Схемы строгие: `refineRoom` требует `runNumber === 0` и `game === null` в лобби, `refineWorld`
запрещает динамические сущности в intermission. Тест, парсящий каждую фикстуру, не даёт preview
показать состояние, которого сервер никогда не выдаст, и ломается сам, когда протокол меняется.

### Display показывает статичный кадр

`SpaceshipCanvas` обновляет Phaser только при смене `game.tick`, поэтому неподвижная фикстура —
корректный один кадр, а не сломанная сцена. Живая симуляция отклонена как отдельная задача: она
тянет `game-core` в зависимости display и дублирует часть комнаты.

## Risks / Trade-offs

- [Фикстуры устаревают при изменении протокола] → тест парсинга падает первым и показывает, какое
  поле добавилось.
- [Preview принимают за проверку поведения] → он проверяет только верстку; поведение остаётся за
  unit-тестами и Playwright.
- [Preview-код остаётся в production-бандле] → замерено: Rollup не сворачивает ветку, потому что
  модуль фикстур импортируется статически, поэтому production отключает preview поведением
  (`import.meta.env.DEV`), а не отсутствием кода. Убрать код из бандла можно только динамическим
  импортом, который делает построение фикстуры асинхронным; в этот change он не входит.
- [Ветка preview расходится с боевой] → preview переиспользует те же компоненты и те же обработчики,
  собственная копия верстки не создаётся.

## Migration Plan

Изменение dev-only и не затрагивает protocol: rollback удаляет модуль preview и его ветку в
`App.tsx` обеих апп.
