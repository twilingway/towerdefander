## Why

Верстку controller и display сейчас видно только внутри живой игровой сессии: нужно поднять сервер,
создать комнату, подключить три роли и довести бой до нужной фазы. Из-за этого правка боевого HUD,
панели голосования или экрана результата стоит полного прогона игры, а редкие состояния — отказ
голоса, перегрев пулемёта, поражение по таймауту волны — вручную воспроизводятся с трудом.

Архитектура для дешёвого решения уже есть: UI обеих апп читает только плоский объект
`ControllerRoomView` / `DisplayRoomView`, собранный roomView-адаптером и провалидированный zod. Если
в dev-режиме подставить туда фикстуру, весь экран отрисуется без Colyseus.

## What Changes

- Dev-сборка controller и display поддерживает `?preview=1`: приложение сразу рендерит игровой экран
  из фикстуры и не создаёт сетевого клиента.
- Preview-панель переключает роль (pilot/gunner/shield) и фазу (lobby/combat/intermission/result)
  без перезагрузки страницы, чтобы каждое состояние верстки открывалось за один клик.
- Все игровые команды в preview — no-op: intents, голоса и ready никуда не отправляются, ошибок при
  этом не возникает.
- Фикстуры проходят `controllerRoomViewSchema.parse` / `displayRoomViewSchema.parse`, поэтому
  preview не может показать состояние, недостижимое по протоколу.
- Production-сборка флаг игнорирует.

Не входит в change: живая симуляция `game-core` в браузере, визуальный drag-and-drop редактор
интерфейса, Storybook или другой отдельный рантайм, изменение protocol, server authority и игровых
правил.

## Capabilities

### New Capabilities

- `ui-layout-preview`: dev-режим просмотра верстки controller и display без сервера и без комнаты.

## Impact

- `apps/controller`: модуль preview-фикстур и gate, ветка в `ControllerApp`, панель переключения,
  unit-тесты.
- `apps/display`: то же для `DisplayApp`; Phaser получает статичный снапшот через существующий
  `SpaceshipCanvas`.
- Shared protocol, server authority и игровые правила не меняются. Новых runtime-зависимостей нет.
