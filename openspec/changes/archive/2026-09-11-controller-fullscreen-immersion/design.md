## Context

Controller — единственный клиент, который живёт на телефоне в руках игрока, и единственный, чья
полезная площадь напрямую конкурирует с браузерным chrome. Landscape-first layout уже реализован, но
считает высоту по `100vh` в базовых правилах `styles.css` и не знает про safe-area. Три нужных
браузерных API (Fullscreen, Screen Orientation, Wake Lock) объединяет одно свойство: каждый может
отсутствовать или отказать, и ни один отказ не должен влиять на игровую сессию.

## Goals / Non-Goals

**Goals:** максимум площади под боевые зоны в Chrome на Android, фиксация landscape, экран не
гаснет, полная деградация до текущего поведения при любом отказе.

**Non-Goals:** PWA-манифест и установка на домашний экран, поддержка Safari/iOS, fullscreen для
`apps/display`, кнопка возврата в fullscreen, изменение protocol, authority или баланса.

## Decisions

### Immersive-режим запрашивается на существующих тапах, а не отдельной кнопкой

Fullscreen требует user gesture, и у controller уже есть ровно два тапа, после которых игрок
переходит к управлению: «Подключиться» и «Я готов». Запрос вешается на них, поэтому в тесной боевой
шапке не появляется новый элемент. Альтернатива с отдельной кнопкой отклонена: она занимает место в
landscape HUD, где его и так нет. Следствие, принятое сознательно: после выхода свайпом вернуться в
fullscreen до следующего экрана нечем.

### Запрос не блокирует отправку команды

`joinRoom` и `sendReady` не ждут результата immersive-запроса. Fullscreen может показать системный
диалог или отказать, и задержка команды из-за этого напрямую ухудшила бы игровой опыт. Промисы
завершаются самостоятельно, их отказы поглощаются.

### Браузерные API инжектируются, а не берутся из глобалей

Модуль immersive-режима принимает host-объект с необязательными методами — тем же приёмом, что
`isVisibleDemoMode(search, development, environmentValue)` в `apps/display/src/visibleDemo.ts`.
Тесты controller выполняются без DOM, поэтому логика «есть API / нет API / API отказал» проверяется
unit-тестами без jsdom, а `App.tsx` остаётся тонким вызовом.

### Отсутствие API и отказ API — одна ветка поведения

Chrome-only scope означает, что `webkit`-префиксные варианты не добавляются. Feature-detect и
`catch` ведут в одно и то же состояние: обычный viewport, пустое поле ошибки, рабочее управление.
Это убирает необходимость различать «Safari» и «пользователь отклонил» в коде и в тестах.

### Wake lock переустанавливается по возвращении вкладки

Браузер снимает screen wake lock при скрытии страницы и не восстанавливает его сам. Поэтому lock
запрашивается при подключении и повторно на `visibilitychange`, когда документ снова видим, и
освобождается при выходе из комнаты и размонтировании.

## Risks / Trade-offs

- [Wake Lock требует secure context] → по `http://` на LAN-адресе в dev он молча не выдаётся; это
  ожидаемая деградация, а не дефект, и проверять его нужно на `localhost` или по HTTPS.
- [`screen.orientation.lock` отклоняется на desktop Chrome] → отказ поглощается, fullscreen
  сохраняется.
- [Игрок вышел из fullscreen системным жестом] → сессия и intents не прерываются, потому что выход
  из fullscreen не вызывает `blur`; вернуться можно на следующем тапе «Я готов».
- [`overscroll-behavior: none` меняет прокрутку portrait fallback] → правило ставится на `body`, что
  гасит pull-to-refresh и цепочку overscroll, но оставляет вертикальный fallback прокручиваемым.
- [`100dvh` пересчитывается при сворачивании панелей] → это и есть цель; layout уже использует
  `100dvh` в landscape-медиазапросе, изменение распространяет то же поведение на базовые правила.

## Migration Plan

Изменение controller-only и не затрагивает protocol: rollback возвращает `index.html`, базовые
правила `styles.css` и вызовы в `App.tsx` без серверной миграции.
