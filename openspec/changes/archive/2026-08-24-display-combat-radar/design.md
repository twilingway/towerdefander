## Context

Protocol v12 уже передаёт display поля `machineGun`, `spaceship` и `enemyShips`. Phaser рисует
локальный участок мира с камерой вокруг корабля, а React владеет HUD. Новая информация предназначена
только для визуальной осведомлённости экипажа и не меняет trusted game state.

## Goals / Non-Goals

**Goals:**

- Показать на общем экране authoritative нагрев и перегрев пулемёта.
- Дать команде круглую обзорную карту всей арены с различимыми типами угроз.
- Сохранить fullscreen Phaser canvas, читаемость HUD и совместимость с Android TV браузером.

**Non-Goals:**

- Отдельные маркеры трёх ролей: сейчас все роли управляют одним кораблём.
- Показ снарядов, туман войны, вращение радара, prediction или gameplay-решения на display.
- Изменения protocol, server, simulation, баланса или новые зависимости.

## Decisions

### D1. Радар — отдельный React/SVG HUD-компонент

`CombatRadar` получает `DisplayGameSnapshot`, использует фиксированный квадратный `viewBox` и
круглый `clipPath`. SVG даёт чёткие маркеры и дешёвую масштабируемую отрисовку без второго Phaser
camera/render texture. Phaser остаётся владельцем только игрового мира.

Альтернатива «вторая Phaser camera» отклонена: она сильнее связывает HUD со scene lifecycle,
усложняет React/Phaser boundary и дороже для слабых Android TV GPU.

После сравнительного playtest выбран один экземпляр радара снизу по центру над основным combat HUD.
Положение задаётся CSS и не меняет контракт данных компонента.

### D2. Фиксированная north-up проекция всей authoritative arena

Центр мира `(worldWidth/2, worldHeight/2)` проецируется в центр радара, а `arenaRadius` — в радиус
круглой рабочей области. Оси не вращаются вместе с heading корабля. Относительное положение угроз
поэтому стабильно и легко читается всей командой.

### D3. Только тактически значимые маркеры

Бирюзовый маркер обозначает один общий spaceship, enemy ships — красные. Ракеты, астероиды и обычные
снаряды исключены, чтобы не создавать визуальный шум при 20 Hz snapshots и entity caps. Все marker
keys используют authoritative `entityId`.

### D4. Нагрев остаётся обычным React HUD state

Процент вычисляется безопасной чистой функцией с clamp. `overheated` берётся напрямую из snapshot;
локальные таймеры охлаждения не создаются. Это сохраняет server authority и корректное состояние
после reconnect/rematch.

## Risks / Trade-offs

- [Частые React-обновления до 20 Hz] → простой SVG ограничен текущими enemy caps, компонент
  мемоизируется, обычные projectiles исключены.
- [Мелкие маркеры на телевизоре] → контрастные цвета, светящийся контур и адаптивный диаметр.
- [Enemy оказался за границей из-за повреждённого snapshot] → круглый clip не даёт маркеру выйти за
  рамку радара.
- [Нулевая capacity из повреждённого состояния] → процент возвращает 0 и не создаёт
  `NaN`/`Infinity`.

## Migration Plan

Изменение разворачивается только с новым display bundle. Rollback — возврат React-компонентов и
стилей; комнаты и protocol v12 остаются совместимыми.

## Open Questions

Блокирующих вопросов нет. В будущем PvP/«Голодные игры» потребует отдельного protocol change для
нескольких friendly/hostile player ships.
