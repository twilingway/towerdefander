# Дизайн: PWA дисплея

## Контекст

Дисплей — Vite 8, React, Phaser отдельным чанком; прод отдаёт его nginx из `docker/web.Dockerfile`
(`docker/nginx-static.conf`: `/assets/` на год с `immutable`, `index.html` с `no-store`, всё прочее
падает на `index.html`). Боевая сборка весит 10 МБ: 1.4 МБ чанк Phaser, 1.1 МБ основной чанк, 4.2 МБ
музыки (два трека, каждый в mp3 и ogg), остальное — спрайты, фоны, атласы, затравка баланса.

Локальный соло уже не ходит на сервер (`local-solo-run`), а картинки и звуки грузятся до лобби
(`assetWarmup.ts`). Значит, для работы без сети не хватает только одного: чтобы всё это пережило
закрытие вкладки.

Авторитет не меняется: service worker только отдаёт файлы. Протокол, комната и симуляция не
затрагиваются; сетевые режимы без сети не работают, как и сейчас.

## Решения

### 1. `vite-plugin-pwa` в режиме `generateSW`

Плагин (1.3.0, peer `vite ^8`) собирает воркер на Workbox и пишет в него список файлов сборки с
хешами. Список обновляется сам на каждой сборке, так что устаревший кэш вычищается без нашего кода.

Отвергнуто: свой `sw.js` руками — версионирование кэша, очистка старого и аварийный режим легли бы
на нас. `injectManifest` со своим воркером — понадобится только с пушами; до них не нужен.

### 2. Что кладётся в кэш и как

- **При установке (precache):** всё из сборки, кроме музыки — чанки, затравка, спрайты, фоны, рамки
  HUD, атласы, звуки эффектов, `art/` стартового экрана. Около 6 МБ. Лимит Workbox на файл (2 МБ по
  умолчанию) держит чанк Phaser; поднимать его не нужно.
- **Музыка:** runtime-кэш «сначала кэш» по первому проигрыванию. Бой без неё идёт молча — так
  `AudioBus` уже ведёт себя без загруженного трека.
- **Навигация:** `index.html` — «сначала сеть», из кэша только без сети. Так релиз приходит с первой
  загрузкой при сети, а не через одну, как было бы при «сначала кэш».
- **Сервер игры** (`/health`, `/ships`, Colyseus) не кэшируется и через воркер не идёт вовсе: это
  живые данные чужого происхождения.

### 3. Обновление: `prompt`, решает игрок

Регистрация с `registerType: "prompt"`: новый воркер ставится и ждёт. `registerSW` из
`virtual:pwa-register` вызывает `onNeedRefresh`; обработчик кладёт флаг в маленький стор (по образцу
`model/graphicsQuality.ts`). Стартовый экран и лобби показывают «Есть новая версия — обновить»;
кнопка вызывает `updateSW()`, и страница перезагружается уже на новой сборке.

Бой флаг не читает вовсе: предложение физически не рендерится на экране боя, поэтому перезагрузка
посреди волны невозможна, а не просто маловероятна. Отказ ничего не ломает: закрытая и открытая
заново игра при сети получает новую страницу («сначала сеть») и новый воркер.

Отвергнуто: `autoUpdate` — перезагрузит страницу, когда воркер обновился, в том числе в бою.

### 4. Разработка без воркеров

Регистрация вызывается только при `import.meta.env.PROD`; `devOptions.enabled` оставлен `false` (так
и по умолчанию). Стенды (`pnpm dev`, `demo:visible`, `watch:bots`) и e2e работают на dev-сервере,
поэтому ни на одном из их портов воркер не появится.

`?sw=off` читается до регистрации: снимаются все регистрации этого происхождения, стираются кэши,
регистрация пропускается. Работает и на боевой сборке — это ремонт телефона без DevTools.

Проверка PWA локально — только `vite preview` на отдельном порту; e2e-тест PWA поднимает его сам.

### 5. Аварийный выход: `selfDestroying`

Опция плагина собирает воркер с тем же именем, который удаляет себя и все кэши. По документации
плагина имя воркера и прочие настройки менять нельзя, иначе замена не произойдёт. Аварийная сборка
включается переменной окружения сборки, а не правкой кода, и проверяется до первого релиза с
воркером.

### 6. Заголовки хоста

В `nginx-static.conf` — `location = /sw.js` и `location = /manifest.webmanifest` с
`Cache-Control: no-cache`. Браузер и сам сверяет `sw.js` не реже раза в сутки, но заголовок убирает
сутки ожидания и любой промежуточный кэш прокси.

### 7. Манифест

`name` и `short_name` — «SpaceShip Defender», `display: "fullscreen"`, `orientation: "landscape"`,
тёмный фон и цвет темы из палитры HUD, иконки 192 и 512 плюс maskable. Установленная игра на Android
открывается сразу горизонтально и без адресной строки — то, что сейчас делает кнопка «Повернуть
экран» в браузере.

## Риски

- **Первый релиз с воркером необратим без аварийной сборки.** Поэтому аварийная сборка проверяется
  на предпросмотре до релиза: поставить воркер, выкатить `selfDestroying`, убедиться, что воркер
  исчез.
- **Две вкладки на разных сборках.** Старая вкладка держит старый воркер, пока открыта; `prompt` это
  и подразумевает. Сервер обеих принимает, пока `PROTOCOL_VERSION` совпадает, а при несовпадении
  клиент уже получает `protocol_mismatch`.
- **Место на устройстве.** 6 МБ при установке и до 4 МБ музыки; Chrome даёт происхождению доли
  процента диска — для Redmi 4X это сотни мегабайт.
- **Android TV** с Chrome не работает вовсе, PWA туда не ставится; сюда её доставит оболочка
  Capacitor, для которой эта сборка и её кэш остаются тем же артефактом.
- **iOS** ставит только через «На экран Домой», без закрепления ориентации.
