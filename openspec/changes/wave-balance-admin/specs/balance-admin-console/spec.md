## ADDED Requirements

### Requirement: Активный пресет баланса определяет конфигурацию нового run

Server SHALL хранить пресеты баланса в JSON-файле по пути из `BALANCE_PRESET_PATH` (default
`./data/balance.json`) и SHALL применять активный пресет при создании нового run. Пресет SHALL
содержать полные `enemyArchetypes` и полную `waveCampaign`; частичные архетипы SHALL отклоняться,
поскольку слияние конфигурации поверхностное. Отсутствующий, нечитаемый либо не прошедший валидацию
файл SHALL приводить к работе на встроенных defaults с записью предупреждения в лог и SHALL NOT
мешать старту сервера или созданию комнат. Уже идущий run SHALL продолжать работать на той
конфигурации, с которой стартовал.

#### Scenario: Файл пресетов отсутствует

- **WHEN** server стартует и файла по `BALANCE_PRESET_PATH` нет
- **THEN** комнаты создаются на встроенных defaults, а лог содержит одно предупреждение

#### Scenario: Файл пресетов повреждён

- **WHEN** файл содержит невалидный JSON либо пресет, не прошедший схему
- **THEN** server стартует на defaults, пишет предупреждение и не применяет частично разобранный
  пресет

#### Scenario: Новый run применяет активный пресет

- **WHEN** активный пресет задаёт HP архетипа, отличное от default, и экипаж стартует новый run
- **THEN** enemy этого типа спавнится с заданным HP, а конфигурация run валидируется до первого
  simulation step

#### Scenario: Правка не трогает идущий бой

- **WHEN** активный пресет заменяется во время combat wave
- **THEN** текущий run продолжает шаги на прежней конфигурации, а новая применяется со следующего
  run либо rematch

### Requirement: Admin API управляет пресетами и защищён от удалённого доступа

Server SHALL предоставлять JSON endpoints `GET /admin/balance` (активный пресет и список пресетов),
`GET /admin/balance/defaults` (встроенные defaults), `POST /admin/balance/validate` (проверка без
записи) и `PUT /admin/balance` (сохранение и назначение активным). Без `ADMIN_BALANCE_PASSWORD`
server SHALL разрешать эти endpoints только loopback socket addresses и SHALL NOT доверять
`X-Forwarded-For`; при заданном password server SHALL требовать HTTP Basic credentials
`admin:<password>` и сравнивать secret безопасно. Unauthorized ответ SHALL быть 401 без данных
баланса. Ответы SHALL иметь `Cache-Control: no-store`. Запись SHALL быть атомарной: временный файл и
переименование, чтобы прерванная запись не оставляла повреждённый пресет.

#### Scenario: Localhost читает баланс без password

- **WHEN** password отсутствует и request socket имеет loopback address
- **THEN** server возвращает активный пресет и список пресетов

#### Scenario: LAN-клиент читает баланс без password

- **WHEN** password отсутствует и socket address не loopback, даже с loopback `X-Forwarded-For`
- **THEN** server возвращает 401 без данных баланса

#### Scenario: Оператор сохраняет валидный пресет

- **WHEN** авторизованный `PUT /admin/balance` содержит пресет, проходящий схему и валидацию
  конфигурации симуляции
- **THEN** server атомарно записывает файл, делает пресет активным и возвращает сохранённое
  состояние

#### Scenario: Оператор сохраняет невалидный пресет

- **WHEN** авторизованный запрос содержит пресет с неположительным HP, `unlockWave` меньше единицы
  либо неизвестным enemy kind
- **THEN** server возвращает 400 с описанием проблемы, файл на диске не изменяется и активный пресет
  остаётся прежним

#### Scenario: Оператор проверяет пресет до сохранения

- **WHEN** авторизованный `POST /admin/balance/validate` содержит пресет
- **THEN** server отвечает результатом валидации без изменения файла и активного пресета

### Requirement: Консоль баланса редактирует волны, архетипы и директора

Admin console SHALL позволять редактировать таблицу явных волн (тип, количество, интервал спавна,
сектор появления, переопределения множителей HP и темпа), характеристики каждого enemy archetype
(HP, радиус, скорость, предпочитаемую дистанцию, параметры оружия, стоимость спавна, волну
разблокировки, награды) и параметры процедурного директора. Console SHALL валидировать ввод теми же
схемами, что и server, и SHALL показывать серверную ошибку валидации без потери введённых значений.
Entity caps SHALL быть доступны только для чтения, поскольку они продублированы в protocol и
ограничивают размер публикуемого снапшота.

#### Scenario: Оператор меняет состав волны

- **WHEN** оператор задаёт волне 1 состав из двух `interceptor` с интервалом спавна и сохраняет
- **THEN** console показывает успешное сохранение, а следующий run начинает волну 1 ровно этим
  составом

#### Scenario: Server отклоняет правку

- **WHEN** сохранение возвращает ошибку валидации
- **THEN** console показывает текст ошибки и сохраняет введённые значения в форме для исправления

#### Scenario: Оператор пытается изменить caps

- **WHEN** оператор открывает экран с entity caps
- **THEN** значения показаны, но недоступны для редактирования
