# Tasks

## 1. Ядро: корабли во множественном числе

- [x] 1.1 Типы арены: `ArenaShipState`, `ArenaProjectile`, `ArenaBeam`, `ArenaSimulationState`,
      `ArenaConfig`. Корабль несёт позу, турель с нагревом, щит с фазами, статы и принадлежность.
- [x] 1.2 Спавн: шестнадцать кораблей равномерно по окружности спавн-радиуса, носами внутрь, порядок
      слотов стабилен. Проверка: два прогона с одним seed дают одинаковые стартовые позиции.
- [x] 1.3 Шаг: `advanceArenaSimulation(state, config)` — чистая функция фиксированного шага, которая
      двигает корпуса через `advanceShipPose`, турели и щиты через существующие traverse-функции,
      стволы через `advanceFriendlyWeapon`. Проверка: тест на то, что при пустых вводах состояние
      воспроизводимо тик в тик.
- [x] 1.4 Попадания: снаряд принадлежит стрелявшему кораблю, не бьёт своего владельца, перехват
      щитом цели проверяется до корпуса и тратит энергию. Проверка: выстрел в свой нос не отнимает
      здоровья, выстрел в чужую дугу гасится щитом, выстрел мимо дуги снимает здоровье.
- [x] 1.5 Потолки арены: `16` кораблей, `256` снарядов, `32` ракеты; сумма типизированных потолков
      равна общему. Проверка: тест на равенство сумм, как в кооперативе.

## 2. Кольцо и конец матча

- [x] 2.1 Расписание фаз: безопасный радиус идёт линейно между фазами, дисплей получает текущий и
      следующий радиус. Проверка: тест на границы фаз и на монотонное сжатие.
- [x] 2.2 Урон вне кольца идёт прямо в корпус, минуя щит и его дугу, и растёт от глубины выхода.
      Проверка: корабль с поднятым щитом вне кольца теряет здоровье с той же скоростью, что и без
      щита.
- [x] 2.3 Матч кончается, когда жив один корабль; при истечении срока побеждает наибольшее здоровье,
      при равенстве — никто. Проверка: три теста на три исхода.
- [x] 2.4 Уничтоженный корабль убирается с поля, его снаряды доживают свой срок, а слот помечается
      выбывшим с тиком и убийцей.

## 3. Боты

- [x] 3.1 `arenaWorld.ts` рядом с `crewWorld.ts`: строит `PolicyWorld` для одного слота, подавая
      чужие корабли в `enemies`, их снаряды в `bullets` и `missiles`, и сохраняя кадр камеры как
      границу видимости.
- [x] 3.2 Время и случайность политики берутся из матча: `nowMs = matchTick * fixedStepMs`, поток
      засевается из `matchSeed` и слота, состояние живёт в `botRngState`. Проверка: два прогона
      матча с одним seed совпадают до последнего тика.
- [x] 3.3 Пятнадцать ботов раскладываются по тикам внутри окна `POLICY_TICK_MS`, а не думают в один
      тик. Проверка: в любом тике думает не больше одного бота.
- [x] 3.4 Уровень бота берётся из профилей автопилота, уже редактируемых в консоли; прототип
      стартует на `veteran`.

## 8. Проверка

- [ ] 8.1 `pnpm check` с явным перехватом кода возврата и `pnpm spec:validate`.
- [ ] 8.2 Кооперативные тесты зелёные без правок: ни один общий примитив не изменён. Если изменён —
      назвать какой и почему, отдельной задачей.
- [x] 8.3 Прогон матча без клиента: шестнадцать ботов до победителя, в логе — длительность матча и
      причина конца. Это же служит опорным замером для балансировки кольца.
      `pnpm arena:match` — первый замер: при кампанийных числах матч кончался за 16–21 с и кольцо
      не двигалось ни разу, а десять сидов давали десять одинаковых матчей (симметричная
      расстановка). После сида в расстановке, разброса по всему диску и масштаба живучести
      (корпус ×2,5, урон ×0,7) восемь сидов дают 40–49 с, разных победителей и 1–4 корпуса,
      добитых кольцом.
