      воркспейса сохраняется, dev-зависимости удаляются. Проверка: `docker build` проходит, а
      `docker run` отвечает на `/health`.
- [ ] 1.2 Один образ на три клиента, параметризованный именем приложения и адресами API и
      контроллера. Проверка: собранный `index.html` общего экрана содержит публичный адрес API, а не
      `localhost`.
- [ ] 1.3 nginx статики: SPA-фолбэк, долгий кэш хешированных ассетов, `index.html` без кэша.
      Отдельная конфигурация консоли добавляет прокси `/admin` на API. Проверка:
      `GET /admin/balance` через контейнер консоли доходит до сервера и требует пароль.
- [ ] 1.4 `docker-compose.prod.yml`: четыре сервиса на внешней сети прокси, игровые порты наружу не

      предел комнат задан ниже дефолта. Проверка:
      `docker compose -f docker-compose.prod.yml config`.
- [ ] 1.5 `.dockerignore` и `.env.production.example` с плейсхолдерами; реальные домены и пароли в
      репозиторий не попадают.

## 1a. Затравка баланса

- [ ] 1a.1 Затравочный набор пресетов в репозитории, отдельный от файла, который пишет консоль.
      Релиз наполняет им пустое хранилище и не трогает заполненное. Проверка: релиз на пустом томе
      поднимает игру на затравке; релиз поверх сохранённой настройки её сохраняет.
- [ ] 1a.2 Отдельная команда переноса живой настройки обратно в затравку, с проверкой выгруженного
      документа перед записью. Проверка: выгрузка печатает версию и число пресетов, битую выгрузку
      не записывает.

## 2. Выкладка

- [ ] 2.1 Скрипт релиза: ожидание освобождения комнат с ограничением по времени, сборка образов с
      тегом по SHA, переключение compose, проверки, возврат предыдущего образа при провале, чистка
      старых тегов. Проверка: намеренно битый тег завершается возвратом, и игра остаётся доступной.
- [ ] 2.2 Smoke публичного развёртывания: создать комнату через публичный адрес, подключить
      контроллер, отключиться. Проверка: скрипт зелёный против живого развёртывания и красный при
      выключенном апгрейде WebSocket.
- [ ] 2.3 Агент опроса `main` и служба, которая его запускает: сверка с выложенным SHA, проверка
      состояния гейта, один экземпляр за раз, журнал. Проверка: пустой коммит в `main`
      подхватывается после зелёного гейта, повторный запуск при неизменном SHA ничего не делает.
