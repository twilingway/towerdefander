# Tasks

## 1. Продвижение баланса дев-стенда в затравку

- [x] 1.1 Скрипт `apps/server/scripts/promote-balance-seed.mjs`: читает файл дев-стенда
      (`BALANCE_PRESET_PATH` или путь по умолчанию сервера), прогоняет его через
      `migrateBalanceDocument`, проверяет `balancePresetsFileSchema`, пишет
      `apps/server/presets/production.json` и прогоняет его Prettier. Проверка: запуск на текущем
      файле дев-стенда даёт затравку в текущей версии формата, а
      `pnpm exec prettier --check apps/server/presets/production.json` проходит.
- [x] 1.2 Ревизия: скрипт читает `apps/server/presets/production.revision`, увеличивает на единицу и
      записывает вместе с затравкой, но только когда документ отличается от прежней затравки;
      совпадение сообщается и ревизию не двигает. Проверка: два запуска подряд — второй печатает,
      что продвигать нечего, и оставляет число прежним.
- [x] 1.3 Отказы: отсутствующий файл дев-стенда, неразбираемый JSON и документ без пресетов
      завершают скрипт ошибкой, не тронув ни затравку, ни ревизию. Проверка: node-тест по образцу
      `apps/server/scripts/autopilot-stats.node-test.mjs` на временных каталогах.
- [x] 1.4 Команда `balance:promote` в корневом `package.json`, и её строка в таблице команд
      `CLAUDE.md`. Проверка: `pnpm balance:promote --help` печатает использование.

## 2. Доставка затравки релизом

- [x] 2.1 `seed_balance_volume()` в `scripts/deploy-production.sh` сравнивает ревизию чекаута с
      `/data/.balance-seed-revision`: больше — применяет, не больше — выходит молча. Проверка:
      `bash -n scripts/deploy-production.sh`, затем прогон извлечённых функций со стабами `docker` и
      `compose` на временном каталоге, с числом больше и меньше. Настоящий том — в 4.3.
- [x] 2.2 Перед перезаписью прежний `/data/balance.json` сохраняется рядом под именем с применяемой
      ревизией, после записи выполняется `compose restart space-api` и записывается применённая
      ревизия. Проверка: в том же прогоне после применения лежат оба файла, а записанное число равно
      числу чекаута.
- [x] 2.3 Хранилище с балансом, но без ревизии, усыновляется: ревизия записывается, файл не
      трогается. Пустое хранилище наполняется как прежде. Проверка: два прогона в том же стенде — с
      файлом без ревизии и полностью пустом.
- [x] 2.4 Затравка проверяется до записи (разбирается как JSON, содержит непустой список пресетов);
      непрошедшая оставляет том нетронутым и не роняет релиз. Проверка: прогоны на неразбираемой
      затравке и на затравке без пресетов — хранилище без изменений, ревизия на месте.
