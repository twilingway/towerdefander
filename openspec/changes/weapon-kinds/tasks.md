## 6. Проверка

- [x] 6.1 Кинетика не сдвинулась: тот же стенд, те же сиды — волна min 5, медиана 8, среднее 7.1,
      max 10; очки медиана 1261, среднее 1121.8; длина 520.5 с. Совпало с задачей 1.1 до последнего
      числа.
- [x] 6.2 Три пресета на одном корпусе, те же сиды. Первый заход развалился: кинетика медиана 8 /
      среднее 7.1, лазер 5 / 5.6, ракета 10 / 9.7. Причин две. Первая — бот вёл упреждение и для
      луча, то есть систематически целился мимо; для hitscan-ствола стенд теперь подставляет в
      решение упреждения «бесконечную» скорость, и лазер бьёт туда, где цель есть, а не туда, где
      она будет. Вторая — при одинаковом уроне лазер платит вдвое меньшей дальностью и ничего за это
      не получает, а ракета почти не мажет и получает всё.
- [x] 6.2.1 После правки прицела и одной настроечной итерации по урону — лазеру ×1.6, ракете ×0.6 —
      все три легли в один диапазон: медиана **8** у каждого, среднее 7.1 / 7.8 / 7.1, max 10 у
      всех. Это и есть результат change: способ доставки доводится до общего диапазона теми числами,
      которые у ствола уже есть. Множители ×1.6 и ×0.6 — стартовые значения для «Клинка» и
      «Бастиона» в следующем change, а не правка умолчаний: умолчания остаются кинетическими и
      нетронутыми.
- [x] 6.3 `pnpm benchmark:combat`: `pureFixedStep` p50 `0.1392`, p95 `0.2768`,
      `pureFixedStepP95AtMost2Ms` истинно. Честно: худший случай бенчмарка кинетический, так что
      цену луча и ракеты он не меряет — их цена видна в длине прогонов выше.
- [x] 6.4 `pnpm format:check`, `pnpm lint`, `pnpm typecheck` чисто; protocol 78/78, game-core
