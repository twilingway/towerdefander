## Context

Репозиторий ведёт историю Git и активные OpenSpec-изменения, а `pnpm demo:visible` уже создаёт
изолированный локальный бой в Chrome. Эти источники достаточны для отчёта, но сейчас требуют ручной
сверки и не сохраняют нужные кадры как набор материалов ролика.

## Goals / Non-Goals

**Goals:**

- Для указанной локальной даты собрать проверяемые Git-факты и относящиеся к ним OpenSpec-изменения
  в один Markdown-файл.
- Дать агенту единый skill, превращающий эти факты в короткий, понятный зрителю сценарий и shot
  list, не выдумывая сделанную работу.
- Разрешить visible demo сохранить два PNG-кадра: готовый интерфейс комнаты и активный бой.

**Non-Goals:**

- Автоматически публиковать ролик, входить в YouTube или генерировать видео/озвучку.
- Менять game-core, сетевой протокол, баланс либо production UI.
- Интерпретировать незафиксированные изменения как выполненную работу.

## Decisions

### Локальный Node-скрипт — источник фактов

Скрипт читает только `git` и файлы рабочего дерева, принимает дату `YYYY-MM-DD` и пишет результат в
игнорируемый каталог `artifacts/daily-videos/<date>/`. Он не использует сеть и новые пакеты. Коммиты
связываются с OpenSpec по затронутым путям `openspec/changes/<change>/`.

Отклонено: попросить модель каждый раз вручную выполнять набор Git-команд. Это не даёт повторяемого
исходника и увеличивает риск пропустить change.

### Skill преобразует факты в авторский материал

Skill обязан сперва запустить или прочитать отчёт-исходник, затем отделить подтверждённые факты от
формулировок для диктора. Он выбирает 2–4 понятных зрителю изменения, короткий hook и кадры к
каждому тезису; если за день нет коммитов, он прямо сообщает об этом.

Отклонено: попытка автоматически получить «человеческий» текст только шаблоном Node-скрипта. Такой
шаблон не сможет разумно объяснить зрителю технический смысл diff.

### Кадры сохраняет существующий visible-demo harness

При явно заданном `DEMO_CAPTURE_DIR` harness сохраняет `lobby.png` после создания комнаты и
`combat.png`, когда в кадре одновременно видны атака и активный щит. Каталог обязан находиться
внутри `artifacts/daily-videos`, чтобы capture не мог записать в произвольное место. Без переменной
запуск остается без побочных файлов.

Отклонено: снимать произвольный пользовательский Chrome. Изолированная демо-комната уже даёт
воспроизводимый, сервер-authoritative бой и не затрагивает активные вкладки пользователя.

## Risks / Trade-offs

- [Коммит не ссылается на OpenSpec] → отчёт показывает его как Git-факт без придуманной связи с
  change.
- [В выбранный момент не появились снаряды или щит] → harness продолжает бой, пока не получит кадр;
  пользователь видит, что `combat.png` не создан, если рано остановит прогон.
- [Chrome или demo не запускается на машине] → отчёт-исходник всё равно создаётся; причина capture
  остаётся видимой в ошибке demo.
- [Артефакты будут случайно добавлены в Git] → весь `artifacts/` игнорируется.

## Migration Plan

Изменение добавляет опциональные developer-tools. Откат — удалить новые skill/скрипт и параметр
capture; игровые сохранения, протокол и развёртывание не затрагиваются.

## Open Questions

Нет: публикация и монтаж остаются ручным авторским этапом.

## Extended delivery pipeline

`pnpm daily:video --date YYYY-MM-DD` сначала строит Markdown-источник по Git/OpenSpec, затем
выбирает последнюю ревизию дня и запускает demo только в detached worktree. Основное дерево не
переключается и его грязные файлы не являются доказательством отчёта. Если historical revision не
содержит harness или opt-in WebM, `status.md` фиксирует ограничение, а MP4 не имитируется.

Версионируемый `scripts/daily-ui-catalog.json` связывает экран с URL, viewport, readiness selector,
`data-testid` таба/панели и исходниками. В capture попадают только записи, чьи исходники менялись в
выбранных коммитах. Playwright является основным средством: запись физического экрана остаётся
fallback для внешних окон и не входит в стандартный поток.

Windows SpeechSynthesis использует только установленный мужской голос `ru-RU` и получает SSML с
паузами, пониженным темпом и отмеченными ударениями. Если такого голоса нет, озвучка и черновой
ролик честно пропускаются; женский голос не используется как подмена. FFmpeg дополнительно
экспортирует `gameplay-raw.mp4` без аудиодорожки, текста и наложений для ручного монтажа. FFmpeg
проверяется через PATH, затем через установку `Gyan.FFmpeg` из WinGet, и собирает реальный WebM, UI
PNG и ASS-титры в H.264/AAC 1080×1920/30 fps. Статический Node-сервер показывает локальный
календарь, Markdown, изображения и MP4; публикации в сеть нет.

Для UI-изображений админки historical observer на время запускает сервер и Vite из собственного
detached worktree на локальных портах, передаёт Vite адрес исторического сервера через
`ADMIN_API_TARGET` и останавливает оба процесса до удаления worktree. Каталог поддерживает
стабильные test id, а для старых ревизий — текстовую вкладку как совместимый fallback; это не
позволяет заменить экран версией из основного дерева.
