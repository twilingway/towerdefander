# Arcadia Effects — авторинг и запекание

Инструмент: [Arcadia Effects](https://github.com/xaidan777/Arcadia-Effects) (MIT) — автономный
редактор 2D-частиц на ванильном JS + Canvas2D, подключён git submodule-ом в `tools/arcadia-effects`.
Это **не npm-пакет**: в его репозитории нет ни одного `package.json`, зависимостей у него ноль, и
собирать его нечем. После клона нужен `git submodule update --init --recursive`.

Внутри submodule папка называется `Arcada Effects` — именно так, с пробелом и без второй `i`. Любой
путь к ней в скрипте требует кавычек.

## Границы

- **Файлы submodule не редактируются никогда.** Он — движок рендера, а не наш код.
- **Наши эффекты живут в нашем репозитории**, в `packages/fx-assets/effects/*.json`. В `library/`
  submodule-а мы ничего не кладём: `pnpm fx:bake` передаёт эффект движку объектом.
- **Атласы пересобираются только через `pnpm fx:bake`.** `packages/fx-assets/src/manifest.ts`
  генерируется этой командой; правки руками смоет следующая сборка, а
  `scripts/bake-fx-atlases.node-test.mjs` их поймает.
- **`doc.id` и `id` каждого слоя задаются явно и не меняются между итерациями.** Без них гидрация
  сгенерит случайные, и редактор при каждой перезагрузке будет считать эффект новым.
- **Данные — по-английски**: имя эффекта, имена слоёв. Русский — только в `effects/catalogue.json`,
  это наши строки для консоли.

## Команды

```bash
pnpm fx:bake                      # все эффекты -> atlases/*.png + *.meta.json + src/manifest.ts
pnpm fx:bake --only plasma-exhaust # один эффект; манифест при этом НЕ перезаписывается
pnpm fx:bake --headed             # то же в видимом браузере
pnpm fx:edit                      # НАШИ эффекты в редакторе, http://localhost:35179
pnpm fx:editor                    # заводская библиотека submodule, http://localhost:5179
```

**Ручная доводка — `pnpm fx:edit`.** `scripts/run-fx-editor.mjs` раздаёт тот же UI редактора, но
библиотекой ему служит `packages/fx-assets/effects`, поэтому Save пишет прямо в исходник, и порт
взят из харнессного блока — работает одновременно с `pnpm dev`, чего `fx:editor` не может.

Три вещи, которые он делает за тебя, и они не косметические:

1. **Save попадает в тот файл, из которого открыли.** Родной сервер называет файл по имени эффекта
   (`safeName(body.name)`), то есть «Shield Band» уехал бы в `Shield Band.json` рядом с
   `shield-band.json`, и запекание продолжило бы брать старый. Скрипт ищет цель по `doc.id` — ещё
   одна причина, почему id обязателен и не меняется.
2. **Прогоняет prettier.** Редактор пишет `JSON.stringify` одной строкой, и `format:check` роняет
   гейт на первом шаге.
3. **Запекает `--only <id>` после сохранения.** Игра читает атлас, а не исходник, поэтому правка не
   видна до перезапекания; после него нужен **F5 на вкладке дисплея** — Phaser держит уже
   загруженную текстуру, HMR её не заменит. `--no-bake` отключает это.

**Перед коммитом — полный `pnpm fx:bake`.** `--only` осознанно не трогает `src/manifest.ts`, так что
записанные в нём размеры файлов остаются старыми; `scripts/bake-fx-atlases.node-test.mjs` это
поймает.

Валидатор редактора, headless и без DOM — гоняй его до запекания, он ловит опечатки в ключах,
неверные enum-ы и трек не по месту:

```bash
cd "tools/arcadia-effects/Arcada Effects"
node tools/validate.mjs "../../../packages/fx-assets/effects/plasma-exhaust.json"
```

**`pnpm fx:editor` конфликтует с `pnpm dev`.** Порт 5179 прошит в `server.mjs` намертво, а Vite при
занятых портах ползёт вверх от 5173 и на четвёртом приложении занимает как раз 5179. Проверить:
`curl -s localhost:5179 | grep -o '<title>[^<]*'`. Поэтому `fx:bake` **не** поднимает его сервер —
он раздаёт статику редактора сам, на 35179, из харнессного блока.

## Пайплайн запекания

`scripts/bake-fx-atlases.mjs`: поднимает свою статику над папкой редактора, открывает страницу
системным Chrome (`channel: "chrome"` — как во всём репозитории, скачанных браузеров Playwright
здесь нет), и для каждого исходника делает в странице:

```js
const doc = await new Promise((ok) => AFX.Model.loadEffectFile(file, ok));
AFX.state.doc = doc;
AFX.touchAll();
const { canvas, info } = AFX.Atlas.build(doc); // info = frameWidth/Height, cols, rows, frames, fps, duration, mode
```

Дальше считает максимум альфы по каждой ячейке и **падает, если хоть один кадр пустой**. Это
единственное место, которое отличает эффект, отрендеривший пустоту, от валидного PNG.

Симуляция детерминирована — фиксированный шаг 1/120 с, сидированный RNG, — поэтому один и тот же
JSON даёт попиксельно тот же атлас, а итерации сравнимы напрямую.

## Посмотреть результат, не открывая редактор

Атласы прозрачные, и в любом просмотрщике прозрачность рисуется белым — аддитивная струя на белом
выглядит серой кашей. Правильный способ: испечь ревью-копию в режиме `black`, движок сам положит её
на чёрный.

```bash
mkdir -p /tmp/fxreview && cp packages/fx-assets/effects/*.json /tmp/fxreview/
# в копиях выставить doc.exp.mode = "black"
node scripts/bake-fx-atlases.mjs --effects /tmp/fxreview --out /tmp/fxreview \
  --only plasma-exhaust,muzzle-flash,explosion,debris-burst
```

`--only` со всеми id обязателен: иначе прогон из чужой папки перезапишет настоящий манифест.

## Формат эффекта

Один JSON: `{ "app": "arcadia-effects", "v": 2, "doc": {...}, "tex": {} }`. `v` — версия схемы
(`Model.SCHEMA`, сейчас 2; файлы `v < 2` получают `em.subStep = false`). Текстуры, если есть, лежат
в `tex` как data-URL; у наших эффектов их нет — все спрайты процедурные.

`doc`: `comp {w,h,dur,fps}`, `cam {comp}`, `exp {cols,rows,frames,cellW,cellH,t0,t1,mode,thr,ss}`,
`textures[]`, `layers[]`. **`layers[0]` — верхний слой.** Типы слоёв: `emitter`, `sprite`, `atlas`,
`postfx`.

**JSON пишется разреженно.** `Model.hydrate` дозаполняет всё отсутствующее фабричными дефолтами, так
что писать нужно только отличия. Полная схема — `docs/FORMAT.md` submodule-а (23 КБ), рецепты по
архетипам — `skills/afx-effect-authoring/SKILL.md`. **Читать эталон из `library/` перед сборкой
похожего эффекта**: `Flame Pro.json` (пламя-луп), `Explosion.json` (взрыв, 7 слоёв, доведён руками),
`Shockwave.json`, `Sparks.json`, `railgun.json`, `Lightning Strike` (в `fxpresets.js`).

### Две ловушки дефолтов

1. Эмиттер без `em.bursts` получает burst на 24 частицы. Для потока — `"rate": N, "bursts": []`.
2. Слой-спрайт без явных `opacity` и `sp.scale` получает заводскую анимацию появления. Задавать оба
   явно.

### Координаты и время

- `(0,0)` — центр композиции, **Y вниз**: `gravY: 380` — падение, `gravY: -60` — подъём.
- Скорости px/с: ~100 лениво, ~300 средне, 600+ выстрел. Жизнь: 0.3–0.5 резко, 0.8–1.2 плавно.
- Время ключей трека — **от начала слоя**, поэтому перенос слоя двигает анимацию вместе с ним.
- `start` может быть отрицательным — пре-ролл: к нулю композиции частицы уже в полёте. У эмиттера
  `start..end` — окно эмиссии, частицы доживают после `end`; у спрайта — окно видимости.
- `cam.comp` — наклон камеры в градусах. **У нас вид строго сверху, значит 0.** Эталоны написаны под
  изометрию (37): при переносе снимать не только `cam.comp`, но и подгонки под неё —
  `sp.aspect`/`sp.rot` у кольца волны были подобраны под сплющенную камеру и сверху читаются
  наклонными эллипсами.

### Треки и кривые

- Трек: число либо `{"keys":[{"t":0,"v":1,"i":{"m":"ease"},"o":{"m":"ease"}}]}`; режимы
  `lin | ease | hold | cust` (`h:[x,y]`).
- **Анимируются только**: у слоя `opacity glowL fadeX fadeY fadeR`; у `em`
  `x y sx sy angle spread speed rate`; у `pt` `size gravX gravY turbAmp`; у `sp`
  `x y scale rot glow color`. Остальное — статика, валидатор ловит трек не по месту.
- Кривые за жизнь (`t` 0..1): `sizeOL`, `opacityOL` как `{"pts":[{"t":0,"v":1},…]}`. Градиент `grad`
  — цвет за жизнь **без альфы**, альфа живёт только в `opacityOL`.

### Спрайты частиц

`soft` (мягкий круг), `dot`, `ring` (`p.th`), `square`, `poly` (`p.n`), `star`, `streak` (штрих для
искр с `alignVel`+`stretch`), `spark`, `flame` (язык, острие в +X, `p.taper`), `ember`, `smoke`
(масса огня и дыма), `blob`, `shard` (обломки). У `smoke`/`blob`/`shard` четыре варианта,
`p.var: 0..3` фиксирует.

### Что решает картинку

- **`add` — огонь, энергия, вспышки; `normal` — дым, обломки.** Тёмное на `add` невидимо.
- **Альфа частицы на `add` держится низкой — 0.03…0.1 для массы, до ~0.35 для редких элементов.
  Яркость набирается перекрытием.** Пик 0.9 на 26 перекрывающихся частицах даёт белый шар вместо
  эффекта; это была настоящая ошибка в первой версии `muzzle-flash`.
- **Сумма аддитивных слоёв держится около единицы, если цвет эффекта важен.** Аддитивное сложение
  упирает старший канал в 255 и продолжает поднимать остальные, поэтому синий эффект при перебором
  сложении становится циан-белым, а не «ярче синим». У `shield-band` это стоило трёх итераций: плита
  0.95 + ореол 0.5 + ядро + искры дали на экране циан, и e2e-спек `shieldGlow` перестал находить щит
  по его собственному синему (`blue ≥ 170`, `blue − green ≥ 40`, `green − red ≥ 50`). Лечится не
  яркостью, а бюджетом: сумма ≈ 1 при синедоминантном цвете, а «живость» берётся противофазой
  пульсаций (`meander(..., invert=True)`), а не добавкой ещё одного слоя.
- **Тонкую длинную полосу одним спрайтом не сделать: `sp.aspect` зажат в 8** (`engine.js`,
  `AFX.clamp(fx.aspect || 1, 0.2, 8)` и `sxm = base * aspect`), а высота спрайта равна `sp.size`.
  Значит полоса 512×36 — это два-три слоя, а не один, и `soft` даёт градиентный профиль, `square` —
  ровный.
- **`turbMode: 'curl'`** — вихревое поле в мировых координатах, соседние частицы едут связной
  струёй; всё текучее хочет именно его. `turbScale` — размер вихря, `turbRise` — поле всплывает с
  плюмом, `turbRamp` — ламинарный низ. `'noise'` даёт дрожание без структуры.
- **Языки и рвань режет постэффект `displace`, а не спрайты.** Ставить над огнём, но под искрами:
  размазанная искра перестаёт быть искрой. `scale` ≈ четверть ширины объекта, `aspect` 2–3 тянет
  складки вверх, `ramp`/`y0`/`soft` успокаивают основание — без них вихрь растаскивает низ в светлую
  лужу.
- **`drag` решает длину струи.** Путь частицы при `v(t) = v0·e^(-drag·t)` равен
  `(v0/drag)·(1 - e^(-drag·life))`. `drag 2.6` при `speed 190` и `life 0.46` даёт 87 px — свечка;
  `drag 1.3` при `speed 600` и `life 0.62` даёт 255 px — сопло. Считать это до запекания дешевле,
  чем крутить наугад.
- **`rate` треком с меандром 4 Гц** — плюм срывается кольцами, а не течёт трубой. У слоя «языков»
  фаза сдвигается на полпериода: отрыв происходит между выбросами.

## Правила атласа

- **Аспект композиции = аспект ячейки.** Ячейка — это вписанная копия ВСЕЙ композиции
  (`fitK = min(cellW/compW, cellH/compH)`, по центру). Совпадают аспекты — композиция заполняет
  ячейку ровно, и кромка композиции ложится на кромку кадра. Не совпадают — появляются поля, и
  привязка спрайта по краю перестаёт работать. `144×384` и `48×128` — оба 0.375.
- **Кадры сэмплируются по центрам интервалов** `t0..t1`, поэтому первый кадр burst-эффекта не
  пустой. `t1: -1` — до конца композиции.
- **`t1` не должен уезжать за последний живой кадр.** У `muzzle-flash` слои кончались на 0.14 с, а
  `t1: -1` тянул окно до 0.25 — последний кадр вышел пустым, и запекание упало. Либо крой `t1`, либо
  удлиняй хвост.
- **Луп: окно `t0..t1` — целое число периодов пыха, и в стационаре.** У выхлопа период 0.25 с, окно
  1.5…2.0 — два периода, а к 1.5 с всё уже вышло на режим (ничто не живёт дольше 0.62 с). Иначе стык
  лупа дёргается.
- **`frames ≤ cols·rows`**, иначе движок молча кламплит.
- **Потолок 512 КБ на атлас.** Гладкость решает число кадров, резкость — размер ячейки; при перевесе
  режь ячейку, а не кадры.
- `mode`: `rgba` (наш случай), `black`, `mask` (+`thr`). `ss: 2` — суперсэмплинг.

## Соглашение об ориентации

**Направленный эффект авторится смотрящим вверх (`-Y`), с источником на нижней кромке композиции.**
Одно соглашение на весь каталог — у потребителя одно правило поворота, а не по одному на эффект.
Флаг `oriented` в `effects/catalogue.json` это фиксирует.

Отсюда геометрия на стороне Phaser: нос корабля смотрит в `+X` при `rotation 0`, спрайт ставится с
`origin (0.5, 1)` — то есть источник эффекта прикалывается к точке, откуда он идёт, и спрайт вокруг
неё же вращается.

Знак поворота **зависит от того, куда эффект уходит**, и это два разных случая:

```text
уходит ПРОТИВ носа (струя двигателя)   rotation = heading - PI/2   EXHAUST_ROTATION_OFFSET
уходит ПО стволу   (дульная вспышка)   rotation = bearing + PI/2   MUZZLE_ROTATION_OFFSET
```

Спрайт при повороте `t` посылает свою локальную `-Y` по `(sin t, -cos t)`. Струе нужно
`(-cos h, -sin h)` — это `t = h - PI/2`; вспышке нужно `(cos a, sin a)` — это `t = a + PI/2`. Оба
знака в `spaceshipViewModel.ts` вместе с выводом, и оба покрыты тестами, потому что **эта ошибка уже
случилась**: у дульной вспышки был переиспользован знак струи, и конус смотрел внутрь корпуса, из
которого стреляли.

Вторая половина той же ошибки — точка. Точка выхода — это **срез** ствола, а не его крепление:
крепление башни есть ось её вращения, и вспышка на нём оказывается посреди корпуса. Симуляция
стреляет из `origin + направление * (радиус корпуса + радиус снаряда)`
(`spaceshipSimulation.ts:576,630`), и дисплей считает то же самое в `getMuzzlePoint`. Направление
берётся из скорости снаряда, а не из угла башни: пушка стреляет по сведённому прицелу.

## Как атлас попадает в приложение

`packages/fx-assets` — общий пакет, потому что атласы нужны и дисплею, и консоли.

- `effects/*.json` — исходники, `effects/catalogue.json` — наши метаданные (title, category, hint,
  `oriented`, `loop`).
- `atlases/<id>.png` + `<id>.meta.json` — вывод запекания, коммитятся.
- `src/manifest.ts` — генерируется; `url` берётся через
  `new URL("../atlases/<id>.png", import.meta.url).href` **строковым литералом**: именно эту форму
  Vite переписывает в хешированный ассет. Динамическая строка не поедет.

Vite складывает в `dist` все четыре атласа обоих приложений, даже неиспользуемые: ассет эмитится по
статической ссылке. По сети клиент качает только тот, который реально загрузили, — `new URL` даёт
строку и ничего не запрашивает.

Дисплей грузит лениво внутри `create()` (`load.spritesheet` + `load.once("complete")` +
`load.start()`), потому что сцена сейчас создаётся синхронно и `preload` сдвинул бы весь порядок
запуска; создание спрайта закрыто проверкой `textures.exists`. Консоль ничего не грузит кодом — кадр
показывается сдвигом `background-position` у одного `div`.
