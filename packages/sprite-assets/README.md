# Растровый арт каталога

Пакет, а не папка внутри дисплея, потому что спрайты рисуют двое: дисплей ставит их на поле в бою, а
консоль баланса показывает их миниатюрами в выборе внешнего вида. Одна копия на диске, а
`new URL(..., import.meta.url)` в `src/manifest.ts` — то, за чем идёт сборщик, поэтому файл попадает
в сборку того приложения, которое его импортировало.

- `sources/sprites/` — исходные PNG, по одному на идентификатор каталога;
- `sprites/` — собранные WebP, их читают приложения;
- `src/manifest.ts` — генерируемый манифест: адрес, размеры, ячейки, байты.

| Идентификатор          | Что это                  | Ячеек | Исходник |
| ---------------------- | ------------------------ | ----- | -------- |
| `sprite-player`        | Корабль игрока           | 1     | 286×388  |
| `sprite-enemy-fighter` | Вражеский истребитель    | 1     | 311×344  |
| `sprite-enemy-orb`     | Вражеская сфера          | 1     | 280×302  |
| `sprite-enemy-heavy`   | Вражеский тяжёлый        | 1     | 327×404  |
| `sprite-asteroids`     | Атлас из трёх астероидов | 3     | 768×256  |

## Откуда арт

Все пять картинок взяты из прототипа оператора `spaceship-defender-map-19400-v6.html`, где они
лежали встроенными data-URI. 2026-09-13 оператор подтвердил, что арт его и может лежать в публичном
репозитории.

У третьего камня атласа в исходнике срезан правый край. Он перенесён как есть.

## Сборка

```bash
pnpm sprites:build
```

Нужен ffmpeg в PATH — тот же, что для `art:prepare`. Скрипт `scripts/build-sprite-assets.mjs`:

1. обрезает каждую ячейку по её непрозрачной рамке (`alphaextract,cropdetect`);
2. вписывает её в ячейку 256 и центрирует — так спрайт достаёт до своего радиуса, какие бы поля ни
   оставил художник;
3. кладёт ячейки в ряд и дополняет лист до ширины-степени двойки, потому что Phaser строит мипмапы
   только для таких текстур;
4. кодирует WebP с альфой, качество 85.

Собранные файлы весят от 20 до 53 КиБ против 131–148 КБ исходных PNG.

## Добавить спрайт

1. Положить PNG в `sources/sprites/<id>.png`. Если это лист из нескольких ячеек, описать его строкой
   в `SHEETS` в скрипте сборки.
2. Назвать идентификатор в каталоге протокола: `VISUAL_ASSET_IDS` и запись `sprite(...)` в
   `packages/protocol/src/visualCatalog.ts`.
3. Выполнить `pnpm sprites:build`.

`scripts/build-sprite-assets.node-test.mjs` не даст разойтись исходникам, манифесту, файлам и
каталогу протокола.

## Фон неба

`sources/backdrops/<id>.png` → `backdrops/<id>.webp`, в манифесте — `BACKDROP_ARTS`. Картинка неба
не режется на ячейки и не дополняется до степени двойки: она рисуется размером примерно с экран, а
NPOT-текстура остаётся без мипмапов — механизма, из-за которого по старому небу ползла полоса.

| Идентификатор | Что это                | Исходник |
| ------------- | ---------------------- | -------- |
| `deep-nebula` | Туманность со звёздами | 1672×941 |

Картинка взята из того же прототипа оператора. Её идентификатор должен стоять в `BACKDROP_IMAGES` в
`packages/protocol/src/visualCatalog.ts`: node-тест сверяет список с файлами.

## Рамки HUD

`sources/hud/<id>.png` → `hud/<id>.webp`, в манифесте — `HUD_ARTS`. Рамка — готовая картинка поверх
поля: без ячеек и без степени двойки. Каждая уменьшается до двойной ширины, которую она занимает на
экране 1080p; ширина стоит строкой в `HUD_FRAMES` скрипта сборки, высота следует пропорциям
исходника. У `ui-status` перед уменьшением стёрта кнопка паузы: прямоугольник `x 930, y 0, 224×224`
исходника очищается вместе с альфой. Потолок node-теста — 160 КиБ на файл.

| Идентификатор   | Что это                                           | Исходник | Собрано |
| --------------- | ------------------------------------------------- | -------- | ------- |
| `ui-info`       | Сведения: три строки                              | 1767×559 | 780×247 |
| `ui-timer`      | Круг таймера с усами                              | 2036×447 | 880×193 |
| `ui-status`     | Четыре полосы: 11 ячеек у верхней, по 10 у прочих | 1154×636 | 660×364 |
| `ui-stick-left` | Кольцо стика, одно на оба                         | 768×758  | 410×405 |
| `ui-knob-move`  | Голубая ручка левого стика                        | 256×256  | 128×128 |
| `ui-knob-aim`   | Оранжевая ручка правого стика                     | 256×256  | 128×128 |
| `ui-radar`      | Круг радара с крыльями                            | 1444×807 | 600×335 |

Рамки взяты из того же прототипа оператора. Правое кольцо стика в прототипе совпадает с левым байт в
байт, поэтому файл один.
