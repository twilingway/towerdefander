# Развёртывание

Публичный стенд игры: общий экран и контроллеры открываются из интернета, консоль баланса остаётся
внутри локальной сети, а вливание в `main` выкатывает релиз само. Проектные решения и отвергнутые
варианты — в `openspec/changes/production-deployment/`; здесь только то, что нужно оператору.

## Схема

```text
интернет ──80/443──> nginx proxy manager ──> space-display:80   общий экран
                                        ──> space-control:80    контроллеры
                                        ──> space-api:2567      Colyseus HTTP + WebSocket
локальная сеть ──8081──> space-admin:80 ──/admin──> space-api:2567
                         space-api ──> том space-api-data:/data  баланс и отчёты
```

Четыре контейнера живут в одном compose-проекте `space` на внешней сети обратного прокси. Наружу
опубликованы только 80 и 443 самого прокси. Консоль слушает 8081 в локальной сети; порт 2567
публикуется на loopback и нужен человеку для диагностики, релиз им не пользуется.

## Что нужно один раз

### 1. Записи DNS

Три записи A на публичный адрес хоста:

| Имя             | Тип | Значение        |
| --------------- | --- | --------------- |
| `space`         | A   | публичный адрес |
| `control.space` | A   | публичный адрес |
| `api.space`     | A   | публичный адрес |

Остальные записи зоны трогать не нужно. В частности, запись `mail` должна существовать, пока на неё
указывает MX: MX без адреса ломает входящую почту домена, а `+mx` в SPF — исходящую.

### 2. Каталог развёртывания

```bash
mkdir -p ~/space-prod/state
git clone https://github.com/<owner>/<repo>.git ~/space-prod/repo
cp ~/space-prod/repo/.env.production.example ~/space-prod/.env.production
chmod 600 ~/space-prod/.env.production
```

Заполнить `.env.production`: домены, `ADMIN_BALANCE_PASSWORD`, `ROOM_STATS_PASSWORD` (например
`openssl rand -base64 24`), `DEPLOY_REPO`. Файл живёт **вне** рабочей копии: релиз переключает
`repo/` на любой коммит, а секреты от этого не зависят.

Пароли администратора в проде обязательны. Сервер разрешает доступ без пароля только с loopback, а
за обратным прокси адрес сокета — адрес прокси, поэтому без пароля консоль отвечает 401 из локальной
сети. Доверять `X-Forwarded-For` вместо этого нельзя: подделанный заголовок стал бы обходом
авторизации.

### 3. Ресурсы Docker

Тик симуляции идёт 20 Гц и упирается в одно ядро, а комнаты процесса делят один event loop: одна
лишняя комната роняет частоту у всех сразу. Если Docker работает в виртуальной машине (colima,
Docker Desktop), ей нужно столько ядер, чтобы тик не делил их с посторонними сервисами:

```bash
colima stop && colima start --cpu 6 --memory 8
docker info --format '{{.NCPU}} CPU, {{.MemTotal}} bytes'
```

Перезапуск виртуальной машины перезапускает **все** контейнеры на хосте, включая посторонние.

`ROOM_MAX_CONCURRENT` в `.env.production` держим ниже упакованного значения по умолчанию: 30 было
измерено на 12-поточной машине.

### 4. Первый релиз

```bash
~/space-prod/repo/scripts/deploy-production.sh --sha origin/main --no-smoke
```

`--no-smoke` только на первом запуске: домены ещё не проксируются, проверять снаружи нечего.

### 5. Обратный прокси

Три Proxy Host, у всех Let's Encrypt и Force SSL:

| Домен                   | Куда               | Особое             |
| ----------------------- | ------------------ | ------------------ |
| `space.<домен>`         | `space-display:80` | —                  |
| `control.space.<домен>` | `space-control:80` | —                  |
| `api.space.<домен>`     | `space-api:2567`   | Websockets Support |

Апгрейд WebSocket на домене API — не деталь: без него матчмейкинг ответит, комната создастся и сразу
исчезнет, то есть отказ будет выглядеть как баг игры. Ровно это проверяет smoke релиза.

На домене API обязательно закрыть административные пути. Игровой API и консоль живут в одном
процессе на одном порту, поэтому публикация домена API иначе выносит наружу и `/admin/balance`, и
`/stats/rooms` — под одним лишь паролем. В Advanced этого Proxy Host:

```nginx
location ~ ^/(admin|stats)(/|$) {
  return 404;
}
```

Консоли это не мешает: она ходит к API напрямую по сети Docker из своего контейнера, а не через
публичный домен. Отказ именно 404, а не 401, чтобы снаружи не было видно, что здесь есть к чему
подбирать пароль. Smoke релиза проверяет и это.

Заголовки CORS на этих маршрутах ставит сам Colyseus, на все свои express-маршруты сразу, — поэтому
граница здесь проходит по прокси, а не по заголовку.

Прокси должен быть в той же сети Docker, что и контейнеры (`PROXY_NETWORK`, по умолчанию
`public_net`).

### 6. Агент автообновления

```bash
cp ~/space-prod/repo/deploy/com.twiling.space-deploy.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.twiling.space-deploy.plist
```

Агент раз в минуту спрашивает у GitHub, куда указывает `main`, и, если гейт качества по этому
коммиту зелёный, вызывает релиз. Входящие подключения к машине не нужны, и чужой код на ней не
исполняется — поэтому не self-hosted runner: на публичном репозитории PR из форка приносит свою
версию workflow-файла.

## Обновление

Обычный путь — влить в `main` и ничего не делать. Руками:

```bash
~/space-prod/repo/scripts/deploy-production.sh            # текущий origin/main
~/space-prod/repo/scripts/deploy-production.sh --sha <sha> # конкретный коммит
```

Порядок одного релиза:

1. Образы собираются **до** ожидания комнат — сборка не трогает работающий стек, игроки её не
   замечают.
2. Релиз ждёт закрытия живых комнат, но не дольше `DEPLOY_DRAIN_MINUTES`, после чего обновляется всё
   равно. Предупреждения игрокам и таймер — предмет отдельного change'а про режим техработ; пока его
   нет, перезапуск для идущей комнаты выглядит как обрыв связи с возвратом на экран входа.
3. Стек переключается на теги нового коммита, затем проверяются здоровье и публичный smoke.
4. Провал любой проверки возвращает предыдущие образы.

Журналы: `~/space-prod/state/deploy.log` (релизы) и `agent.log` (опрос ветки).

## Откат

Автоматический — часть релиза. Вручную, на записанный предыдущий тег:

```bash
cat ~/space-prod/state/tag-history          # новые сверху
cd ~/space-prod/repo
IMAGE_TAG=<тег> docker-compose --project-name space \
  --env-file ~/space-prod/.env.production -f docker-compose.prod.yml up -d
```

На диске держатся три последних релиза. Откат не трогает том с балансом.

## Баланс: том и seed

Баланс живёт в двух местах, и это намеренно.

- **Том `space-api-data`** — то, что читает игра и пишет консоль. Здесь настройка, которую вы
  правите перед сессией.
- **`apps/server/presets/production.json` в репозитории** — затравка. Из неё поднимается хост, где
  игры ещё не было.

Релиз копирует затравку на том **только когда том пуст**. Это единственное правило, которое здесь
важно: выкатка никогда не кладёт числа из чекаута поверх того, что вы сохранили из консоли. Иначе
релиз молча откатывал бы вашу настройку, и заметили бы это уже в бою.

Расходятся они тоже намеренно. Когда живая настройка устоялась и её пора зафиксировать в истории:

```bash
scripts/export-balance-seed.sh
git add apps/server/presets/production.json && git commit
```

Сам файл `apps/server/data/balance.json` в репозиторий не входит: его переписывает целиком консоль,
в нём есть `version`, который двигают миграции, и он был бы вторым источником правды рядом с
дефолтами в коде.

## Данные

Отредактированный из консоли баланс и отчёты статистики лежат на именованном томе `space-api-data`,
а не в образе и не в рабочей копии, поэтому переживают любое число релизов.

```bash
docker run --rm -v space_space-api-data:/data alpine tar czf - -C /data . > balance-backup.tgz
```

Имя тома с префиксом проекта; точное — из `docker volume ls`.

## Проверка живого стенда

```bash
cd ~/space-prod/repo
set -a; . ~/space-prod/.env.production; set +a
node apps/controller/scripts/production-smoke.mjs
```

Smoke проверяет `/health`, публичный каталог корпусов вместе с его CORS-заголовком, отдачу обоих
клиентских сайтов и настоящее создание комнаты с посадкой контроллера через публичный адрес.

## Если что-то не так

| Симптом                                  | Причина                                                                    |
| ---------------------------------------- | -------------------------------------------------------------------------- |
| Комната создаётся и сразу исчезает       | на домене API не включён Websockets Support                                |
| Консоль отвечает 401 из локальной сети   | не задан `ADMIN_BALANCE_PASSWORD`                                          |
| `/admin` открыт по публичному домену API | в Advanced этого Proxy Host нет отказа на `/admin` и `/stats`              |
| На экране выбора корпуса нет названий    | ответ `/ships` не дошёл — проверить smoke и заголовок origin               |
| После релиза общий экран белый           | закэшированный `index.html`; он отдаётся с `no-store`, проверить прокси    |
| Агент молчит                             | `agent.log`, затем `launchctl print gui/$(id -u)/com.twiling.space-deploy` |
